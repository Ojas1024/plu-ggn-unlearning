Method

The baselines, why freezing the preprocessor fails, what PLU-GGN does, and how everything is evaluated.

Baselines and methods

Model: L2-regularized logistic regression (λ = 10, fixed in advance and not tuned on test data). For each deletion request every method is compared against oracle retraining:

No unlearning

Keep the old weights and the old preprocessor. The trivial baseline.

Gradient ascent

5 small steps uphill on the deleted patients' loss. Preprocessor frozen.

Standard influence (GGN)

One Newton step that removes the deleted rows' gradient (Koh & Liang 2017; Guo et al. 2020). Preprocessor frozen.

PLU-GGN (ours)

(1) Exactly downdate the preprocessor. (2) Add the gradient change caused by the new coordinates, gshift. (3) Take a Gauss–Newton step in the new coordinates. Optional 2nd Newton step.

Why a frozen preprocessor hurts

The total change from the original weights to the retrained ones has two parts:

θ*r − θ̂ = [sample removal] + [coordinate change]
Standard influence estimates only the first part. Removing the heaviest hospital users shrinks σ for number_inpatient from 1.20 to 0.78, so the same real-world effect needs a smaller coefficient per standardized unit. Removing those patients' gradient pushes the same coefficient up. When the two parts point in opposite directions, standard influence can land further from retraining than doing nothing.

This is an identity plus an argument about direction, not a theorem; the Results page checks it.

The coefficients at 3% deletion

number_inpatient: oracle 0.253, full model 0.328, standard influence 0.390. The removal step moves it the wrong way.

PLU-GGN in three steps

  1. Exact preprocessor downdate. Subtract the deleted rows' (count, Σx, Σx²) and (category count, Σy) and recompute μ, σ and encodings: O(|Df|). The stored design matrix is re-expressed by the affine map z' = (σ/σ')·z + (μ − μ')/σ'. Imputed cells stay 0 and categorical columns are re-mapped.
  2. Pipeline-shift gradient. gshift = Σretained [∇ℓ(new features) − ∇ℓ(old features)], evaluated at the old weights.
  3. Gauss–Newton step in the new coordinates: θ = θ̂ + Gnew−1(grem − gshift). PLU-GGN-2 adds one more Newton step.

Cost: only step 1 is O(|Df|). Steps 2–3 make one pass over the retained data (O(|Dr|d² + d³), d = 13) but need no iterative optimization, so PLU-GGN is cheaper than retraining but not free.

Evaluation design

  • Split: patient-grouped 80/20 (19,995 train / 5,005 test), fixed before any comparison. Test data is used only for reporting.
  • Weight error ‖θ − θ*r‖: the standard unlearning metric. Frozen-φ methods express θ in different coordinates, so we also report
  • Function-space error: mean KL divergence between the method's and the oracle's test predictions, which doesn't depend on coordinates.
  • Pipeline leak: how far the deployed μ, σ are from the retrained ones (100% = unchanged from before deletion).
  • Sanity check: test PR-AUC (prevalence baseline ; number_inpatient alone ).
  • Exact reference: L-BFGS stops about 10−5 from the optimum, so the oracle is polished with Newton steps. Only the ordinary L-BFGS refit is timed.
  • Robustness: 5 seeds that change both the patient split and the missingness mask; a random-deletion control; deletion sizes from 0.5% to 8%.
